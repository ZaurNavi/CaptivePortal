- Подключение приложения и его запуск **не изменять**: `captive-portal.service` использует `/opt/captivprod-portal-v2fix/run.py`; зафиксированное состояние Git `b6152459421b48514ddc8af114bcc96e30351cf7`.
- Текущий скрипт аудита находится в прилагаемом файле `captivprod-audit-ro.py`, SHA-256: `cd52410a60deb8e83596a2146ad636fae769bbafda3cf9c13ebeabcb1cec35f4`.

## Задача SysAdmin (однократная установка, отдельная проверка)

1. Проверить файл и его SHA-256, отсутствие неизвестных изменений и то, что он не отправляет наружу события/секреты.
2. Доставить `captivprod-audit-ro.py` в `/home/sysadmin` штатным защищённым каналом. Выполнить команды из сопровождающей инструкции `CAPTIVPROD_AUDIT_READONLY_ACCESS_SETUP_2026-10-16.md` для установки в `/usr/local/sbin/captivprod-audit-ro` под `root:root` с правами `0755`.
3. Через `visudo` выдать в отдельном файле sudoers **только** разрешение `sysadmin ALL=(root) NOPASSWD: /usr/local/sbin/captivprod-audit-ro ""` — без аргументов, без оболочки, редакторов, `sudo ALL` или опасных обходных путей.
4. Проверить владельцев/права `/usr/local/sbin` и самого скрипта, синтаксис sudoers, затем подтвердить, что `sudo -n /usr/local/sbin/captivprod-audit-ro` выдаёт корректный JSON с состояниями компонентов и агрегированными показателями SQLite/очередей.
5. Подтвердить, что журнал или ответ не содержат паролей, токенов, приватных ключей, сырых MAC/IP посетителей и строк пользовательских БД. Проверить, что аргументами нельзя расширить допустимые операции.
6. Предоставить Tech Lead результат **без секретов**: `PASS/FAIL`, версию скрипта, SHA-256, результат проверочного вызова и список неподтверждённых контуров. Если доступ через Desktop Commander остаётся заблокированным самой платформой, не менять SSH-защиту и не обходить ограничение; передать агрегированный JSON обычным утверждённым способом.

## Контроль и границы

- **Запрещены:** изменение сервиса/приложения, `chown`/`chmod 777` данных, `docker`-группа для SSH-пользователя, открытие секретов, запись в SQLite, checkpoint, очистка очереди, рестарты и изменение сети.
- **Нужны два снимка:** разовые счётчики сами по себе не доказывают отсутствие backlog. Следующая задача Tech Lead — сопоставить снимки по времени, а очереди — по их реальной семантике в коде.
- Для **будущих изменений** production оформляются конкретная задача, план отката и отдельное подтверждение Owner; постоянного `root` без ограничений этот TASK не создаёт.
- Откат доступа: удалить отдельный файл `/etc/sudoers.d/captivprod-audit-ro` и `/usr/local/sbin/captivprod-audit-ro`, не трогая приложения. Отзыв SSH-ключа — отдельное действие.

**Acceptance:** `AUDIT_HELPER_INSTALLED=PASS`, `SUDOERS_SCOPED=PASS`, `OUTPUT_REDACTED=PASS`, `PRODUCTION_CHANGED=NO`; платформа удалённого доступа — самостоятельный контроль, не подменять его правами Linux.
