# Выбор класса модели и контроль AI-расходов

Status: current
Updated: 2026-08-04

Документ не привязан к конкретному AI vendor или названию модели.

| Тип задачи | Рекомендуемый класс |
|---|---|
| Документация, форматирование, fixture | лёгкий |
| Локальный test или простой defect | лёгкий или средний |
| Реализация точного TASK | средний |
| Архитектура, concurrency, persistence, сложный defect | сильный reasoning |
| Критическое финальное review | средний или сильный |

Для сложной задачи: сильная модель готовит PLAN и критические решения; средняя реализует утверждённый PLAN.

Сильную модель не использовать автоматически для rename, formatting, fixtures, текста или локальной проверки.

## Контроль расхода

Техлид оценивает:

- ширину scope;
- число прочитанных файлов;
- объём переданных logs;
- число переделок;
- выбор класса модели;
- отсутствие targeted tests;
- повторное восстановление уже документированной архитектуры;
- ложные repository-action claims.

Не требуется считать каждый token. Обязателен Agent execution summary из handoff.md.
